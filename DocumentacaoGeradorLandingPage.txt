================================================================================
  1. O QUE E O PRODUTO
================================================================================

Plataforma web (SaaS) para criacao de landing pages personalizada para
escritorios de contabilidade, com DUAS CAMADAS DISTINTAS:

CAMADA ADMIN (Backoffice Interno):
  - Equipe interna cria, importa e edita templates/layouts
  - Editor avancado com Puck (MIT) para construcao visual de templates
  - Controle granular de quais propriedades o cliente final pode editar
  - Gestao da biblioteca de componentes
  - Operacoes: criar novo, importar layout, editar existente,
    "Salvar Novo" ou "Salvar Alteracoes"

CAMADA CLIENTE (Usuarios Finais):
  - Contadores e escritorios criam paginas profissionais sem conhecimento tecnico
  - Dois caminhos: editor visual com drag-and-drop OU templates prontos
  - Edita apenas propriedades permitidas pelo admin (textos, imagens, cores)
  - Exporta como HTML + CSS + JS para hospedagem propria

Diferencial: templates e componentes feitos especificamente para o nicho
contabil (servicos contabeis, equipe, captacao de leads, WhatsApp, FAQ, etc.)


================================================================================
  2. PUBLICO-ALVO
================================================================================

Interno (Admin):
  - Equipe da plataforma (designers, desenvolvedores)
  - Necessidade: criar e gerenciar templates sem deploy de codigo

Externo (Clientes):
  - Escritorios de contabilidade (1 a 20 funcionarios)
  - Contadores autonomos que precisam de presenca digital
  - Consultorias e franquias contabeis
  - Empresas de abertura de CNPJ/MEI


================================================================================
  3. SISTEMA DE PAPEIS
================================================================================

ADMIN (role = 'admin'):
  - Acesso: /admin/* + todas as rotas de cliente
  - Pode: criar/editar/importar templates, gerenciar componentes
  - Pode: definir quais props o cliente pode editar (flag editavel_cliente)

CLIENTE (role = 'cliente'):
  - Acesso: rotas de cliente apenas
  - Pode: usar templates, editar propriedades permitidas, exportar landing pages
  - Nao pode: acessar /admin/*, modificar props bloqueadas

Implementacao:
  - Coluna role em profiles (admin | cliente)
  - Funcao PostgreSQL is_admin() para RLS
  - Sync role -> JWT custom claims via trigger
  - AdminGuard para rotas /admin/*

================================================================================
  6. STACK TECNICA
================================================================================

Frontend:
  - React 18 + Vite + TypeScript 5 (strict mode)
  - Tailwind CSS (utility-first, sem CSS-in-JS)
  - shadcn/ui + CVA para variantes de componentes
  - Framer Motion para animacoes
  - Zod para validacao de formularios
  - Arquitetura: Bulletproof React (feature-based)
  - Estado: useState + useReducer + Context API (sem Redux/Zustand)

Admin Builder:
  - Puck (MIT, React, JSON output) para construcao de templates
  - Tailwind v4 compativel

Cliente DnD:
  - dnd-kit para drag-and-drop no editor do cliente

Componentes Landing Page (todos MIT):
  - shadcn/ui blocks — componentes base (headers, features, footers)
  - Aceternity UI — efeitos visuais (parallax, spotlight, glow)
  - Magic UI — animacoes avancadas (marquee, particles, blur)
  - BLOQUEADO: Tailwind UI (licenca proibe uso em page builders)

Backend:
  - Supabase Auth (email/senha + OAuth)
  - Supabase Database (PostgreSQL com RLS obrigatorio)
  - Supabase Storage (imagens, thumbnails, logos)
  - Supabase Edge Functions (Deno) para logica sensivel

Seguranca:
  - RLS (Row Level Security) obrigatorio em TODAS as tabelas
  - is_admin() funcao PostgreSQL para policies de admin
  - Zod obrigatorio em TODAS as Edge Functions
  - Erros no formato RFC 7807 Problem Details
  - Nunca expor segredos no client (VITE_ prefix = publico, sem prefix = privado)
  - Logging com prefixo [nome-funcao][request-id]
  - CORS sem wildcard em producao
  - LGPD: PII apenas via views mascaradas

  9. BANCO DE DADOS (Tabelas Principais)
================================================================================

CORE:
  profiles              -> Dados do usuario (nome, empresa, logo, ROLE)
  templates             -> Modelos criados pelo admin (JSONB com editavel_cliente)
  componentes_biblioteca -> Registro de componentes disponiveis
  projetos              -> Landing pages criadas pelo cliente (SNAPSHOT em JSONB)
  leads                 -> Leads capturados via formularios

PLATAFORMA (da Fase 4):
  admin_settings        -> Configuracoes da plataforma (key-value)
  comunicados           -> Anuncios e comunicados (info, warning, maintenance, update)
  comunicados_lidos     -> Tracking de leitura por usuario
  modulos_aprendizado   -> Modulos de aprendizado
  aulas                 -> Aulas dos modulos (video, anexos)
  aulas_anexos          -> Anexos das aulas
  progresso_aprendizado -> Progresso do usuario por aula
  comentarios_aulas     -> Comentarios (com moderacao)
  avaliacoes_aulas      -> Notas de 1 a 5
  dicas_ajuda           -> Dicas contextuais por pagina/secao
  paginas_legais        -> Termos, privacidade, LGPD (com versionamento)
  paginas_legais_versoes -> Historico de versoes
  aceites_termos        -> Aceitacao por usuario
  visualizacoes_onboarding -> Tracking de onboarding visto

Total: 19 tabelas

Todas as tabelas com RLS + FORCE ROW LEVEL SECURITY.
Templates, componentes e modulos publicados sao publicos para leitura.
Admins tem full access em tabelas administrativas.
Demais tabelas sao restritas por user_id.
Funcao is_admin() usada em policies de admin.
